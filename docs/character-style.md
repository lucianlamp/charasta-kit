# キャラのスタイル（スタンダード体型、チビ体型、生き物）

3 つ目のスタイル「生き物」(`creature`)は `docs/creature.md`。以下はスタンダードとチビの仕様。

キャラを「スタイル」で 2 つに分けて管理する。名前は「スタンダード体型」と「チビ体型」。用途(VTuber、動画、ゲームなど)は画面に書かない。

この文書の「スタンダード」「チビ」は、画面の「スタンダード体型」「チビ体型」のこと（名前は `public/edition.mjs` の版の種類ごとの名前）。

| スタイル | id | 表情 | 形式と検査 |
|---|---|---|---|
| スタンダード体型 | `standard` | シェイプキー(キットの表情を `studio/vroid/kit_fcl.py` で Fcl の 57 キーへ) | VRoid 形式の検査 |
| チビ体型 | `chibi` | 画像(表情スタジオの顔テクスチャ) | 軽い版、三角形の数 |

## データ
- character.json に `style`(`standard` か `chibi`)。新しいキャラは作るときに選ぶ(必須)。前からのキャラで `style` が無いものは「未設定」と扱う(自動で決めない)。
- `PATCH /api/characters/<id>` で `style` を変えられる(許すキーに足す)。画面では「変えると表情を作り直すことになる」と確かめてから変える。
- 一覧の API とキャラ 1 体の API に `style` を出す。

## 画面

`character.json` の `style`(`standard`、`chibi`、`creature`)。生き物の決めごとは `docs/creature.md`。画面の名前は「スタンダード体型」「チビ体型」「生き物」だけで、用途の言葉(VTuber、動画、ゲーム)と、人型、デフォルメの語は出さない。札の色は スタンダードが `--run`(青)、チビが `--warn`(橙)、生き物が `--creature`(緑、`#5FD38D`。パネルの `#15181D` の上でコントラスト約 9.5:1)、未設定は `--muted` の破線。生き物の緑は、選んだ状態と主ボタンに使う `--act`(黄緑)と分けるために足した。

### ライブラリ

- 見出しの下(判断待ちの帯のあと)にタブ「スタンダード体型」「チビ体型」「生き物」「すべて」。それぞれに数を出す。`role="tablist"` と `role="tab"`、選んだタブは `aria-selected="true"`。左右の矢印、Home、End でも移る。
- 未設定(`style` が `null`)のキャラは「すべて」にだけ出て、数も「すべて」にだけ入る。
- 選んだタブは `localStorage` の `charasta.styleTab` に覚える。読み書きが失敗しても動く。覚えたタブが無いときは、スタンダードのキャラがいればスタンダード、いなければすべて。
- タブの下に、そのスタイルで決まることを 1 行で出す。スタンダードは「表情: シェイプキー(Fcl の 57 キー) / 形式: VRoid 形式の検査」、チビは「表情: 画像(顔テクスチャのコマ) / 形式: 軽い版と三角形の数」、生き物は「形式: Blender(骨と動き)」に、生き物のキャラの最新の版の動きの名前を重ねずに足す(例「/ 動き: 止まる、羽ばたく、down、tilt、stare、caw」。6 つを超えたら「など」)。「すべて」では出さない。
- カードの棒の下に、スタイルの札をタグの前に出す。
- 生き物のカード: 4 工程の棒と「完成モデル N」は出さない(VRM の工程なので)。サムネイル(背景が透明の 512×512)は暗い地(`--stage`)に、切らずに収めて出す。名前、版、生き物の札、タグ、動きの 1 行(「動き: 止まる、羽ばたく、down、tilt…」。4 つを超えたら「…」、全部は `title`)と削除のボタン。どこを押しても `#model/<キャラ>`。版が無ければ「版なし」。
- タブに当てはまるキャラがいなければ「このスタイルのキャラはまだない。」。
- スマホの幅(700px 以下)では、4 つのタブを 2×2 にし(375px でも「スタンダード体型」と数が 1 行に入る)、カードは 2 列(375px で 2 列になる最小幅 150px のグリッド)。

### 新しいキャラ

- 枠の最初に「スタイル」の欄。「あとから変えられるが、スタイルを変えると、表情を作り直すことになる。版を取り込んだあとは、生き物とほかのスタイルのあいだでは変えられない。」の文と、3 つの大きな選ぶボタン(`aria-pressed`。幅が足りなければ折り返す)。ボタンには決まることを 2 行で出す。
- その下の「このスタイルで決まること」に、選んだスタイルの作り方・表情・仕上げを出す。選ぶ前は「スタイルを選ぶと、ここに出る。選ぶまで「作り始める」は押せない。」。
  - スタンダード: 作り方 きゃらくる(Tripo Studio)で rig と表情まで / 表情 キットの表情を kit_fcl で Fcl の 57 キーへ / 仕上げ VRoid 形式への変換、輪郭線 0.8 mm、検査
  - チビ: 作り方 きゃらくる(Tripo Studio)で rig まで / 表情 表情スタジオで image_gen の絵を顔テクスチャに / 仕上げ 軽い版、三角形の数の検査
  - 生き物: 作り方 Blender で骨と動きを作り、scripts/import-creature.mjs で取り込む / 表情 なし(動きの Action を使う)
- 初期値は無い。選ぶまで「作り始める」は押せない(確認の枠の `setup` で切り替える)。送る直前にも確かめ、無ければ「スタイル(スタンダード体型、チビ体型、生き物のどれか)を選ぶ」と出す。
- そのあとに今までの「3D の作り方」、キャラ ID、名前。`POST /api/characters` に `style` を入れて送る。
- 生き物を選ぶと「3D の作り方」を隠す(VRM の作り方なので)。「作り始める」は、きゃらくるのアプリを開かずに `POST /api/characters {id, name, style: "creature"}` だけ送り、`#model/<キャラ>`(生き物のページ)へ移る。版は `scripts/import-creature.mjs` で取り込む。

### プロフィールのスタイル

- 候補は `restyleChoices`。版の無いキャラは 3 つから選べる。版があるキャラは、生き物とそれ以外のあいだを移れない(サーバーも `bad-input` で断る)ので、VRM のキャラはスタンダードとチビだけ、生き物は「変える」を出さない。

## 版の検査
キャラのページ(生き物のページも)の右の欄に「検査」を出し、開いたときに自動で読む。`GET /api/characters/<キャラ>/versions/<版>/check`(`lib/version-check.mjs`)。スタイルで中身が分かれる。

- スタンダード: VRoid 形式の検査(`lib/vroid-format.mjs` の `checkVroid`。`scripts/vroid-check.mjs check` と同じ読み方で、手本は `studio/vroid/reference.json`)。手本が無ければ、その旨を返して項目は空にする。
- チビ: 下の項目(`lib/chibi-check.mjs`)。
- 生き物とスタイル未設定: 検査なし。理由を出す(`applicable: false`)。

状態は `ok` / `warn` / `ng`(スタンダードだけ)/ `unknown`(分からない)。項目の形は `{id, label, level, detail}` で、`detail` に測った値を入れる。目安の値が資料に無い項目は `unknown` にして値だけを出す(値を作らない)。

### チビの検査の項目
| 項目 | 判定 |
|---|---|
| 軽い版 | `model-lite.vrm` があれば ok(大きさを並べる)。無ければ warn で `tools/make_lite.py` の使い方を出す |
| 三角形 | model.vrm の合計が 18,000 以下なら ok、超えれば warn(軽い版の数が違えば添える) |
| 材質の数 | 数だけを出す。目安が資料に無いので unknown |
| テクスチャ | 枚数、最大の一辺、展開した大きさ(幅×高さ×4 バイト)を model.vrm と軽い版で並べる。軽い版があればそれを、無ければ model.vrm を上限と比べ、超えれば warn。画像の大きさを読めない、または枚数が違うときは unknown |
| 表情の方式 | 画像の名前が `FaceAtlas` か、節の名前が `Face_layers` なら顔テクスチャ(ok)。Fcl_ のシェイプキーがあれば warn。どちらの手がかりも無ければ unknown(`lib/face-check.mjs` の `faceOf` と同じ判定。docs/face-atlas.md) |

### 目安の値と出典
- 三角形の合計 1.5 万〜1.8 万(スマホのメインキャラ 1 体): 作者の制作手順の資料の「目安」。上限の 18,000 で判定する。同じ資料の実例は合計 14,292。
- テクスチャの上限: `tools/make_lite.py` の既定。元の画像の一辺が 4096 を超えるもの(顔テクスチャなど)は 4096 まで、それ以外は 2048 まで。軽い版の画像は元の画像と同じ番号で比べる。
- 「展開した大きさ」は、画像が GPU に載る量の参考値で、判定には使わない(画像の大きい版を iPhone の Safari で開くとページが落ちる。`tools/make_lite.py` の冒頭の記録)。

### キャッシュ
結果は版のフォルダの `check.json`(`{key, checkedAt, result}`)に置く。`key` は model.vrm と model-lite.vrm の大きさと更新時刻、手本の大きさと更新時刻(スタンダードだけ)、検査の版(`CHECK_VERSION`)。キットでは版の種類(`edition: 'kit'`)も入れる(検査の文に出るスタイルの名前が違うので)。どれかが変われば測り直す。検査の項目を変えたら `CHECK_VERSION` を上げる。
