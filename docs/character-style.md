# キャラのスタイル（スタンダード体型、チビ体型）

生き物のスタイル(`creature`)はキットに無い(`docs/edition.md`)。

キャラを「スタイル」で 2 つに分けて管理する。名前は「スタンダード体型」と「チビ体型」。用途(VTuber、動画、ゲームなど)は画面に書かない。

この文書の「スタンダード」「チビ」は、画面の「スタンダード体型」「チビ体型」のこと（名前は `public/edition.mjs` の版の種類ごとの名前）。

| スタイル | id | 表情 | 形式と検査 |
|---|---|---|---|
| スタンダード体型 | `standard` | シェイプキー(キットの表情を `studio/vroid/kit_fcl.py` で Fcl の 57 キーへ) | VRoid 形式の検査 |
| チビ体型 | `chibi` | 画像(表情スタジオの顔テクスチャ) | 軽量版、三角形の数 |

## データ
- character.json に `style`(`standard` か `chibi`)。新しいキャラは作るときに選ぶ(必須)。前からのキャラで `style` が無いものは「未設定」と扱う(自動で決めない)。
- `PATCH /api/characters/<id>` で `style` を変えられる(許すキーに足す)。画面では「変えると表情を作り直すことになる」と確かめてから変える。
- 一覧の API とキャラ 1 体の API に `style` を出す。

## 画面

`character.json` の `style`(`standard`、`chibi`)。画面の名前は「スタンダード体型」「チビ体型」だけで、用途の言葉(VTuber、動画、ゲーム)と、人型、デフォルメの語は出さない。札の色は スタンダードが `--run`(青)、チビが `--warn`(橙)、未設定は `--muted` の破線。

### ライブラリ

- 見出しの下(判断待ちの帯のあと)にタブ「スタンダード体型」「チビ体型」「すべて」。それぞれに数を出す。`role="tablist"` と `role="tab"`、選んだタブは `aria-selected="true"`。左右の矢印、Home、End でも移る。
- 未設定(`style` が `null`)のキャラは「すべて」にだけ出て、数も「すべて」にだけ入る。
- 選んだタブは `localStorage` の `charasta.styleTab` に覚える。読み書きが失敗しても動く。覚えたタブが無いときは、スタンダードのキャラがいればスタンダード、いなければすべて。
- タブの下に、そのスタイルで決まることを 1 行で出す。内部の名前(Fcl、キーの数、検査の名前)は出さない平易な 1 文で、スタンダードは「表情はシェイプキーで動かす。VRoid と同じ作りかを確認する」、チビは「表情は顔の画像を切り替えて動かす。軽量版があるか、三角形が多すぎないかを確認する」。「すべて」では出さない。
- カードの棒の下に、スタイルの札をタグの前に出す。
- タブに当てはまるキャラがいなければ「このスタイルのキャラはまだない。」。
- スマホの幅(700px 以下)では、3つのタブを 2×2 にし(375px でも「スタンダード体型」と数が 1 行に入る)、カードは 2 列(375px で 2 列になる最小幅 150px のグリッド)。

### 新しいキャラ

- 枠の最初に「スタイル」の欄。「あとから変えられるが、スタイルを変えると、表情を作り直すことになる。」の文と、2 つの大きな選ぶボタン(`aria-pressed`。幅が足りなければ折り返す)。ボタンには決まることを 2 行で出す。
- その下の「このスタイルで決まること」に、選んだスタイルの作り方・表情・仕上げを出す。選ぶ前は「スタイルを選ぶと、ここに出る。選ぶまで「作り始める」は押せない。」。
  - スタンダード: 作り方 選んだ作り方で、骨組みと表情まで作る / 表情 シェイプキーで動かす。VRoid と同じ名前のキーを使う / 仕上げ VRoid 形式への変換、輪郭線 0.8 mm、検査
  - チビ: 作り方 選んだ作り方で、骨組みまで作る / 表情 表情スタジオで描いた顔の絵を、顔の画像にする / 仕上げ 軽量版、三角形の数の検査
- 初期値は無い。選ぶまで「作り始める」は押せない(確認の枠の `setup` で切り替える)。送る直前にも確かめ、無ければ「スタイル(スタンダード体型、チビ体型のどれか)を選ぶ」と出す。
- そのあとに今までの「3D の作り方」、キャラ ID、名前。`POST /api/characters` に `style` を入れて送る。

### プロフィールのスタイル

- 候補は `restyleChoices`。スタンダードとチビから選ぶ。

## バージョンの検査
キャラのページの右の欄に畳んだ「検査」を出し、開いたときに自動で読む。スタンダードは見出しを「VRoid 形式との違い(同じ 2 / 注意 2 / 違う 9)」とし、札を「同じ」「注意」「違う」にする。「違う」は警告色にしない。見出しの下に「VRoid 製のモデルと同じ作りかを見る。モデルが使えるかどうかの判定ではない。」を出す。`GET /api/characters/<キャラ>/versions/<バージョン>/check`(`lib/version-check.mjs`)。スタイルで中身が分かれる。

- スタンダード: VRoid 形式の検査(`lib/vroid-format.mjs` の `checkVroid`。`scripts/vroid-check.mjs check` と同じ読み方で、手本は `studio/vroid/reference.json`)。手本が無ければ、その旨を返して項目は空にする。
- チビ: 下の項目(`lib/chibi-check.mjs`)。
- スタイル未設定: 検査なし。理由を出す(`applicable: false`)。

状態は `ok` / `warn` / `ng`(スタンダードだけ)/ `unknown`(分からない)。項目の形は `{id, label, level, detail}` で、`detail` に測った値を入れる。目安の値が資料に無い項目は `unknown` にして値だけを出す(値を作らない)。

### チビの検査の項目
| 項目 | 判定 |
|---|---|
| 軽量版 | `model-lite.vrm` があれば ok(大きさを並べる)。無ければ warn で `tools/make_lite.py` の使い方を出す |
| 三角形 | model.vrm の合計が 18,000 以下なら ok、超えれば warn(軽量版の数が違えば添える) |
| 材質の数 | 数だけを出す。目安が資料に無いので unknown |
| テクスチャ | 枚数、最大の一辺、展開した大きさ(幅×高さ×4 バイト)を model.vrm と軽量版で並べる。軽量版があればそれを、無ければ model.vrm を上限と比べ、超えれば warn。画像の大きさを読めない、または枚数が違うときは unknown |
| 表情の方式 | 画像の名前が `FaceAtlas` か、節の名前が `Face_layers` なら顔テクスチャ(ok)。Fcl_ のシェイプキーがあれば warn。どちらの手がかりも無ければ unknown(`lib/face-check.mjs` の `faceOf` と同じ判定。docs/face-atlas.md) |

### 目安の値と出典
- 三角形の合計 1.5 万〜1.8 万(スマホのメインキャラ 1 体): 作者の制作手順の資料の「目安」。上限の 18,000 で判定する。同じ資料の実例は合計 14,292。
- テクスチャの上限: `tools/make_lite.py` の既定。元の画像の一辺が 4096 を超えるもの(顔テクスチャなど)は 4096 まで、それ以外は 2048 まで。軽量版の画像は元の画像と同じ番号で比べる。
- 「展開した大きさ」は、画像が GPU に載る量の参考値で、判定には使わない(画像の大きい版を iPhone の Safari で開くとページが落ちる。`tools/make_lite.py` の冒頭の記録)。

### キャッシュ
結果はバージョンのフォルダの `check.json`(`{key, checkedAt, result}`)に置く。`key` は model.vrm と model-lite.vrm の大きさと更新時刻、手本の大きさと更新時刻(スタンダードだけ)、検査の版(`CHECK_VERSION`)。キットでは版の種類(`edition: 'kit'`)も入れる(検査の文に出るスタイルの名前が違うので)。どれかが変われば測り直す。検査の項目を変えたら `CHECK_VERSION` を上げる。
