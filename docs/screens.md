# 画面

ライブラリを最初の画面にし、工程は つくる・モーション・表情・仕上げ の 4 つ。完成モデルは工程の外の別ページ。ジョブは上部バーの引き出しに出す。機能ごとの画面の細かい決まりは、それぞれの文書にある（`docs/README.md`）。

## ジョブの引き出し

ジョブの箱は画面に置かない。上部バーのジョブのボタン（動いている数を出す）で開く引き出しに、新しい順に 8 件出す。外を押すか Esc で閉じる。

- 作成中のものは、作っている一覧の先頭に仮の行で出す。動きはモーションの一覧（`motion-gen`、`video-motion`、`motion-recipe`）、完成モデルは作ったもの（`shoot`、`video`、`voice`）。
- 完了すると `watchJobs` が一覧を読み直す。この処理は箱が無くなっても画面ごとに動かす。
- 開いている画面で失敗したジョブは、仮の行に「失敗」と理由を残す。その画面を離れると消え、引き出しには残る。

## ビューア単体（`/viewer`）

欄の見出しを `<details>` に替えて畳んだだけで、id は消していない（`tools/` と `viewer.mjs` が頼っている）。開いているのはキャラとバージョンとモーション。表情、口、セリフ、再生の設定は畳んである。

### window.viewer

- モーションの再生（一覧は `/api/motions`、表情の時刻表は motion.json の `expressions`）、自動の瞬き、表情のボタン、モーションに合わせた表情
- 口（あいうえお）のボタン、かなの文を「話す」
- セリフ（そのキャラの lines）を再生して口を合わせる。`emotion` があれば話す間その表情
- 画面の中でキャラとバージョンを切り替える（読み込み直す）
- `window.viewer` の道具はそのまま残す: `vrm`、`motion`、`camera`、`controls`、`face(d)`、`paused`、`step(dt)`、`speak(text)`、`playVoice(...)`（セリフを指定）、`voice`（`time` を手で進める撮影用）、`speech`、`mouthOverride`、`skirtTest()`
- 撮影の道具（`tools/`）がこの API で動くこと

## ビューアを iframe で載せる理由

動きと完成モデルの画面は `/viewer?embed=1` を iframe で載せ、親から `window.viewer` を呼ぶ（動き: `play`、`time`、`duration`、`seek`、`hold`、`follow`、`footIK`、`weapon`、`reloadMotions`。完成モデル: `prepareShot`、`aimShot`、`shotExpression`、`shotBackground`、`playVoice`）。

- 撮影の道具（`tools/common.mjs` の `viewerUrl`、`HIDE_PANEL_CSS`）は `/viewer` の DOM と `window.viewer` に頼っている。ビューアを同じページへ組み込むより、ページをそのまま残すほうが撮影の結果を変えない（`tools/studio_checks.mjs` の 72 枚が差 0）。
- 画面を移ると iframe ごと捨てられ、WebGL のメモリが返る（iPhone は GPU のメモリが足りなくなりやすい）。

`hold` は `paused` と別のもの。`paused` は撮影の道具が手で姿勢を置くためのもので足の IK を切る。`hold` は再生のバーの停止で、止めた姿勢にも足の IK をかける。

再生のバーのつまみ（`public/scrub.mjs`）は、握っている間 `hold` を立てて、動かすたびに `seek` でその時刻の姿勢へ置く。離したら握る前の再生か停止へ戻す。握り始めは pointerdown だけに頼らず、最初の `input` でも握る（iPhone の Safari で pointerdown が来ない場合に、再生の位置の書き戻しがつまみを戻すのを防ぐ）。つまみは `touch-action: none` で、指が縦にずれてもページのスクロールに奪われない。

## 4 工程の進み具合

3 段階（できている / 途中 / まだ）。出し方は `lib/overview.mjs` の `stageProgress`。記録に無いことは推測しない。

| 工程 | できている | 途中 | まだ |
| --- | --- | --- | --- |
| つくる | バージョンが 1 つ以上ある | バージョンは無いが、作り方の記録か、つながったプロジェクトがある | それ以外 |
| モーション | バージョンがあり、モーションが 1 本以上ある（当てて再生できる） | 使わない | それ以外 |
| 表情 | 最新バージョンの VRM に、感情の表情 5 つ全部の中身がある | 一部だけある、または表情づくりがある | それ以外 |
| 仕上げ | 「バージョンとして保存」を押した表情づくりがある、または体型と揺れものの直しで作ったバージョン（`adjust.json` を持つバージョン）がある、または表情づくりが 1 つも無くバージョンが 1 つ以上ある | 表情づくりに試作があり、まだバージョンにしていない | それ以外 |

- モーションはモーションが全キャラ共通で、キャラごとの完了の記録が無い。言えるのは当てて再生できるかどうかだけなので、途中は使わない。
- 表情は VRM の JSON チャンクの `VRMC_vrm.expressions.preset` の bind の有無で見る。絵の出来は見ない。
- 仕上げは、仕上げでやり残している作業があるかを示す。表情づくりを通らず取り込んだバージョンをそのまま使うキャラ（VRoid 製、Tripo Studio 製など）は、残る作業が無いので「できている」になる。表情づくりを始めて試作だけがあり、バージョンにしていないときは「途中」。完成モデルになるかどうかとは別。

## 完成モデル

キャラごとに、「バージョンとして保存」を押したバージョンすべてと、最新バージョン。`lib/overview.mjs` の `finishedVersions`。最新バージョンを入れるので、「バージョンとして保存」を通していない今あるキャラも完成モデルを持つ。バージョンにしたかどうかは `work.json` の `versions` から読み、`version.json` は変えない（ADR 0002）。

完成モデルでないバージョンも、上部バーで選べば撮ると書き出すを使える。ライブラリのカードの「完成モデル N」が数で、一覧の画面は無い。別のキャラとバージョンへは上部バーで移る。

### プロフィール

完成モデルの画面の上の欄（`public/profile.mjs`）。キャラの記録（`GET /api/characters/<キャラ>`）から出し、保存は `PATCH /api/characters/<キャラ>`（`docs/characters.md`）。

- **名前**: `name` とキャラ ID。ここでは変えない。
- **スタイル**: 名前の横に「スタイル」とスタイルの札(未設定なら「スタイル未設定」)と「変える」。「変える」は確認の枠を開き、「スタイルを変えると、表情を作り直すことになる」と 2 つの選ぶボタンを出す。今と違うスタイルを選ぶまで「変える」は押せない。押すと `PATCH {style}` を送り、札を直して「変えた」と出す。未設定には戻せない(サーバーが `null` を断る)。
- **タグ**: `tags` をチップで並べる。チップを押すと外し、入れて「追加」か Enter で足す。どちらもすぐ保存する。決まりはサーバーと同じ（前後の空白を除いて 1〜20 文字、最大 8 個）で、送る前に画面でも断る。同じタグは足さずに「もう付いている」と出す。
- **声**: 今の `voice` を `provider:id` で出す（無ければ「なし」）。「変える」で声の種類の小さなモーダルを開く（候補の選択か手で入れる名前と「保存」）。保存するとここの表示を直してモーダルを閉じる。
- **メモ**: `note` を textarea で書き換え、「保存」で送る。
- **出演した動画**: `appearances`（保存場所のショートのうち、このキャラが出るもの、更新の新しい順）。題、型（対話型、ダンス MV）、更新日を並べ、押すと `#short/<ID>` の編集画面へ移る。無ければ「出演した動画はまだ無い」。
- メモと出演した動画は「メモと出演した動画（N 本）」の畳みに入れる。広い画面は 3 つの欄を画面の高さに収めるので、プロフィールが高いとビューアが狭くなるため。
- 保存中は「保存中…」、失敗は赤い文で「保存できない: 理由」を出す（声の種類のモーダルと同じ作り）。

## キャラのスタイル

ライブラリのタブ、新しいキャラのスタイルの欄、プロフィールのスタイルは `docs/character-style.md`。

## 作り方

`character.json` の `method`（キットは `tripo` だけ。画面の名前は「きゃらくる（Tripo Studio）」）。ライブラリの「新しいキャラ」でキャラの記録を作るとき(スタイルを選んだあと)に残し、今あるキャラはつくるの画面の選択で残す。「新しいキャラ」の初期値は `tripo`。記録が無ければ「記録なし」と出す。

「作り始める」は、キャラの記録を作り、きゃらくるのアプリ（設定の `charakuruUrl`、既定 `http://127.0.0.1:8766/`）を新しいタブで開く。きゃらすたの依頼は作らない。制作の流れはきゃらくる自身の依頼文が持っていて、同じものを二重に持たないため。きゃらくるのプロジェクトには書き込まない（ADR 0001）。

バージョンの取り込み（`POST /api/characters/<キャラ>/versions`）は、プロジェクトの `work/review.vrm` をコピーする。プロジェクトの工程は `project.charakit` の `project.json` から読む（`projectProgress`、キットの `public/journey.mjs` の判定に合わせた）。

## デザインと違えた所

- **フォント**: README と docs に外部通信を禁じる決めごとは無いので、デザインのとおり Google Fonts の CSS を `public/index.html` で読む。読めなければ OS の日本語フォントになる。撮影の道具が開く `/viewer` では読まない。
- **ジョブの進み具合の棒**: ジョブは割合を持たないので、工程の文と経過の秒を出す。
- **モーションの絞り込み**: 「ダンス」の記録が無いので「そのほか」。出どころの無い分類は作らない。
- **モーションの作るの文**: 「1 本 7 秒ほど」は確認していないので出さない。
- **細かい条件**: デザインに無い 進む向き・終わり方・移動・ラベル は今ある機能なので、「細かい条件」に畳んで残す。
- **モーションの一覧**: 案の行は名前と長さだけだが、利用条件の札、絞り込み、モーションの情報は残した。札は既定の「二次配布 不可」を一覧の行と選択肢（撮る、ダンス MV、つくるの区間）に出さず、個人利用のみ、評価用のみ などそれより強い制限だけを出す（`limitTag`、`optionName`）。選択肢の名前に「評価用」が入っていて札も評価用のときは足さない。「このモーションの情報」と撮るときの利用条件の欄は変えない。公開できないことが一覧で分かるようにするため。

## ステージ

`public/stages.mjs`、`#stages[/<ステージ>]`。stage-studio（設定の `stageStudioDir`）のステージを見る画面。ステージは読むだけで、新しいステージは「新しいステージを依頼」でエージェントに依頼する（`docs/stages.md`）。両方のバージョンにある。入口は上部バーの「ステージ」（「ショート」「動画」の左。キャラの画面でも出す）と、スマホの下のナビの「ステージ」。

- 上の文: 「ステージ <数> 個。ショートと MV の舞台に使う。」。
- 一覧: `stages/catalog.json` の順に、サムネイル（stage-studio の `assets/thumbs/<ステージ>.jpg`、`GET /api/mv/stages/<ステージ>.jpg`）、名前、ID、使っている数（「ショート 2 本・MV 1 本」、無ければ「まだ使っていない」）のカード。押すと `#stages/<ステージ>` でそのステージを選ぶ。選んだカードは枠を `--act` にする。
- 選んだステージ: 名前と ID、サムネイルを大きく（暗い地に、切らずに 270px まで）。stage-studio にあるステージの絵はサムネイルの 1 枚だけなので、ほかの絵は出さない（無いものは作らない）。サムネイルが無ければ「サムネイルなし」と「このステージにはまだ見本の絵が無い。」を出す。
- 使えるもの: 動画の種類ごとのカメラの数（`public/short-camera.mjs` の `camerasFor`。立って話す 14、歩く 1 テイク 5、ダンス MV 8）。カメラも歩く 1 テイクもステージごとの決まりがコードに無い（stage-studio の `stages/*.py` に歩く道の情報は無く、歩く 1 テイクの `take.mark` はショートの側が持つ）ので、どのステージも同じ表にし、「カメラの種類はどのステージでも同じ。」と出す。歩けるかはステージごとには書かない。
- 使っている動画: そのステージを使うショート（カットの `stage` か、ダンス MV の `music.stages`。押すと `#short/<ID>`。型、歩く 1 テイクか、更新日）と、MV の撮った動画（`kind: mv` の `mv.stages`。押すと `#gallery`。キャラ、バージョン、試しか本番か、撮った日）。ショートを書き出した動画はショートとして数えるので、ここには重ねない。
- 広い画面は一覧と選んだステージの 2 列（選んだステージは右、画面の上に留める）。700px 以下は 1 列にし、選んだステージを一覧より先に出す。
- stage-studio が設定されていなければ、ほかの画面と同じ理由の文（`missingNote` の「stage-studio(ステージの描画)(設定の stageStudioDir)」）だけを出す。設定はあるがステージが無ければ「ステージがまだ無い。」と依頼する欄の案内を出す（依頼する欄は出す）。
- 新しいステージの依頼: 上の右の「新しいステージを依頼」の欄と、下の「依頼したステージ」のカード（`docs/stages.md` の「画面」）。
- API: `GET /api/stages` → `{ configured, stages: [{ id, label, thumb, shorts: [{ id, title, style, take, updatedAt }], mvs: [{ id, charId, charName, verId, quality, createdAt }] }] }`（`lib/stages.mjs` の `stageOverview`）。`thumb` はファイルが無ければ `null`。GET 以外は 405。

## 動画ギャラリー

`public/gallery.mjs`。全キャラの撮った動画と MV を新しい順に並べる（`GET /api/shoots`）。絞り込みは すべて、MV、MV の試し、撮った動画 と、キャラ。カードを押すとその場で再生する。ダウンロードと削除（ごみ箱）はカードから。セリフだけの動画は完成モデルの「作ったもの」にあり、ここには出さない。

MV の試しのカードには「本番で書き出す」があり、同じ条件の `mv` ジョブを積む。本番を書き出した試しからは消える。

## ショート

ショートの一覧と編集画面は `docs/shorts.md`、ダンス MV の入口（`#mv`）と「曲とステージ」の欄は `docs/shorts-dance-mv.md`。

## 削除とごみ箱

消す操作はごみ箱へ移すだけで、いつでも戻せる（`docs/characters.md` の「ごみ箱」）。常時目立たせず、控えめに置く。

| 場所 | 操作 |
| --- | --- |
| ライブラリのカード | カードの右下にごみ箱の形のアイコンのボタン（`aria-label` は「<名前> を削除」） |
| つくるのバージョンの表 | 行の末尾の「削除」 |
| モーション | 右の欄の、選んでいるモーションの操作の下の「このモーションを削除」 |
| 完成モデルの作ったもの | 撮った動画の再生のモーダルの「削除」 |
| 撮るのセリフ | 「このセリフを消す」 |
| ライブラリの下 | 「ごみ箱 N 件、合計 MB」のリンク。`#trash` へ |

- 押すと確認の枠（`confirmDialog`）。影響の箇条書き（`GET .../impact` の `effects`）、「ごみ箱から戻せる。」、「やめる」、「ごみ箱へ移す」。断る理由があるときは、箇条書きの下に理由を出し、「ごみ箱へ移す」を押せなくする。`alert`、`confirm` は使わない。
- 色の強調は確定のボタン（`#FFB454`）だけ。
- `#trash`: 1 行に、種類の札、名前、大きさと移した日、「戻す」、控えめな「完全に消す」。旧形式の項目は「戻す」を押せない。「完全に消す」と「ごみ箱を空にする」は、確認の枠で「戻せないことを確かめた」にチェックを入れるまで確定のボタンを押せない。
- バージョンを消すと、選んでいたバージョンが無くなった画面は最新バージョンに戻す（`app.mjs`）。動きの一覧は、合わせたキャラやバージョンを消してあるモーションに「削除済み」と添える。
- ボタンの押せる大きさは 44px 以上（スマホの幅でも）。

## 確かめ
