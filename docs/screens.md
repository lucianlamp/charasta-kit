# 画面

ライブラリを最初の画面にし、工程は つくる・動き・表情・仕上げ の 4 つ。完成モデルは工程の外の別ページ。ジョブは上部バーの引き出しに出す。機能ごとの画面の細かい決まりは、それぞれの文書にある（`docs/README.md`）。

## ジョブの引き出し

ジョブの箱は画面に置かない。上部バーのジョブのボタン（動いている数を出す）で開く引き出しに、新しい順に 8 件出す。外を押すか Esc で閉じる。

- 作成中のものは、作っている一覧の先頭に仮の行で出す。動きはモーションの一覧（`motion-gen`、`video-motion`、`motion-recipe`）、完成モデルは作ったもの（`shoot`、`video`、`voice`）。
- 完了すると `watchJobs` が一覧を読み直す。この処理は箱が無くなっても画面ごとに動かす。
- 開いている画面で失敗したジョブは、仮の行に「失敗」と理由を残す。その画面を離れると消え、引き出しには残る。

## ビューア単体（`/viewer`）

欄の見出しを `<details>` に替えて畳んだだけで、id は消していない（`tools/` と `viewer.mjs` が頼っている）。開いているのはキャラと版とモーション。表情、口、セリフ、再生の設定は畳んである。

### window.viewer

- モーションの再生（一覧は `/api/motions`、表情の時刻表は motion.json の `expressions`）、自動の瞬き、表情のボタン、モーションに合わせた表情
- 口（あいうえお）のボタン、かなの文を「話す」
- セリフ（そのキャラの lines）を再生して口を合わせる。`emotion` があれば話す間その表情
- 画面の中でキャラと版を切り替える（読み込み直す）
- `window.viewer` の道具はそのまま残す: `vrm`、`motion`、`camera`、`controls`、`face(d)`、`paused`、`step(dt)`、`speak(text)`、`playVoice(...)`（セリフを指定）、`voice`（`time` を手で進める撮影用）、`speech`、`mouthOverride`、`skirtTest()`
- 撮影の道具（`tools/`）がこの API で動くこと

## ビューアを iframe で載せる理由

動きと完成モデルの画面は `/viewer?embed=1` を iframe で載せ、親から `window.viewer` を呼ぶ（動き: `play`、`time`、`duration`、`seek`、`hold`、`follow`、`footIK`、`weapon`、`reloadMotions`。完成モデル: `prepareShot`、`aimShot`、`shotExpression`、`shotBackground`、`playVoice`）。

- 撮影の道具（`tools/common.mjs` の `viewerUrl`、`HIDE_PANEL_CSS`）は `/viewer` の DOM と `window.viewer` に頼っている。ビューアを同じページへ組み込むより、ページをそのまま残すほうが撮影の結果を変えない（`tools/studio_checks.mjs` の 72 枚が差 0）。
- 画面を移ると iframe ごと捨てられ、WebGL のメモリが返る（iPhone は GPU のメモリが足りなくなりやすい）。

`hold` は `paused` と別のもの。`paused` は撮影の道具が手で姿勢を置くためのもので足の IK を切る。`hold` は再生のバーの停止で、止めた姿勢にも足の IK をかける。

再生のバーのつまみ（`public/scrub.mjs`）は、握っている間 `hold` を立てて、動かすたびに `seek` でその時刻の姿勢へ置く。離したら握る前の再生か停止へ戻す。握り始めは pointerdown だけに頼らず、最初の `input` でも握る（iPhone の Safari で pointerdown が来ない場合に、再生の位置の書き戻しがつまみを戻すのを防ぐ）。つまみは `touch-action: none` で、指が縦にずれてもページのスクロールに奪われない。

## 4 工程の進み具合

3 段階（できている / 途中 / まだ）。出し方は `lib/overview.mjs` の `stageProgress`。記録に無いことは推測しない。

| 工程 | できている | 途中 | まだ |
| --- | --- | --- | --- |
| つくる | 版が 1 つ以上ある | 版は無いが、作り方の記録か、つながったプロジェクトがある | それ以外 |
| 動き | 版があり、モーションが 1 本以上ある（当てて再生できる） | 使わない | それ以外 |
| 表情 | 最新の版の VRM に、感情の表情 5 つ全部の中身がある | 一部だけある、または表情づくりがある | それ以外 |
| 仕上げ | 「版にする」を押した表情づくりがある | 表情づくりに試作がある | それ以外 |

- 動きはモーションが全キャラ共通で、キャラごとの完了の記録が無い。言えるのは当てて再生できるかどうかだけなので、途中は使わない。
- 表情は VRM の JSON チャンクの `VRMC_vrm.expressions.preset` の bind の有無で見る。絵の出来は見ない。
- 仕上げは、きゃらすたの仕上げの工程を通ったかどうかを示す。工程を通さず取り込んだ版だけのキャラは「まだ」になる。完成モデルになるかどうかとは別。

## 完成モデル

キャラごとに、「版にする」を押した版すべてと、最新の版。`lib/overview.mjs` の `finishedVersions`。最新の版を入れるので、「版にする」を通していない今あるキャラも完成モデルを持つ。版にしたかどうかは `work.json` の `versions` から読み、`version.json` は変えない（ADR 0002）。

完成モデルでない版も、上部バーで選べば撮ると書き出すを使える。ライブラリのカードの「完成モデル N」が数で、一覧の画面は無い。別のキャラと版へは上部バーで移る。

### プロフィール

完成モデルの画面の上の欄（`public/profile.mjs`）。キャラの記録（`GET /api/characters/<キャラ>`）から出し、保存は `PATCH /api/characters/<キャラ>`（`docs/characters.md`）。

- **名前**: `name` とキャラ ID。ここでは変えない。
- **スタイル**: 名前の横に「スタイル」とスタイルの札(未設定なら「スタイル未設定」)と「変える」。「変える」は確認の枠を開き、「スタイルを変えると、表情を作り直すことになる」と 2 つの選ぶボタンを出す。今と違うスタイルを選ぶまで「変える」は押せない。押すと `PATCH {style}` を送り、札を直して「変えた」と出す。未設定には戻せない(サーバーが `null` を断る)。
- **タグ**: `tags` をチップで並べる。チップを押すと外し、入れて「足す」か Enter で足す。どちらもすぐ保存する。決まりはサーバーと同じ（前後の空白を除いて 1〜20 文字、最大 8 個）で、送る前に画面でも断る。同じタグは足さずに「もう付いている」と出す。
- **声**: 今の `voice` を `provider:id` で出す（無ければ「なし」）。「変える」で右の欄の「声の種類」の畳み（細かい条件の中）を開く。そこで保存すると、ここの表示も直る。
- **メモ**: `note` を textarea で書き換え、「保存」で送る。
- **出演した動画**: `appearances`（保存場所のショートのうち、このキャラが出るもの、更新の新しい順）。題、型（対話型、ダンス MV）、更新日を並べ、押すと `#short/<ID>` の編集画面へ移る。無ければ「出演した動画はまだ無い」。
- メモと出演した動画は「メモと出演した動画（N 本）」の畳みに入れる。広い画面は 3 つの欄を画面の高さに収めるので、プロフィールが高いとビューアが狭くなるため。
- 保存中は「保存中…」、失敗は赤い文で「保存できない: 理由」を出す（声の種類の欄と同じ作り）。

## 作り方

`character.json` の `method`（キットは `tripo` だけ。画面の名前は「きゃらくる（Tripo Studio）」）。ライブラリの「新しいキャラ」でキャラの記録を作るとき(スタイルを選んだあと)に残し、今あるキャラはつくるの画面の選択で残す。「新しいキャラ」の初期値は `tripo`。記録が無ければ「記録なし」と出す。

「作り始める」は、キャラの記録を作り、きゃらくるのアプリ（設定の `charakuruUrl`、既定 `http://127.0.0.1:8766/`）を新しいタブで開く。きゃらすたの依頼は作らない。制作の流れはきゃらくる自身の依頼文が持っていて、同じものを二重に持たないため。きゃらくるのプロジェクトには書き込まない（ADR 0001）。

版の取り込み（`POST /api/characters/<キャラ>/versions`）は、プロジェクトの `work/review.vrm` をコピーする。プロジェクトの工程は `project.charakit` の `project.json` から読む（`projectProgress`、キットの `public/journey.mjs` の判定に合わせた）。

## デザインと違えた所

- **フォント**: README と docs に外部通信を禁じる決めごとは無いので、デザインのとおり Google Fonts の CSS を `public/index.html` で読む。読めなければ OS の日本語フォントになる。撮影の道具が開く `/viewer` では読まない。
- **ジョブの進み具合の棒**: ジョブは割合を持たないので、工程の文と経過の秒を出す。
- **動きの絞り込み**: 「ダンス」の記録が無いので「そのほか」。出どころの無い分類は作らない。
- **動きの作るの文**: 「1 本 7 秒ほど」は確かめていないので出さない。
- **細かい条件**: デザインに無い 進む向き・終わり方・移動・ラベル は今ある機能なので、「細かい条件」に畳んで残す。
- **動きの一覧**: 案の行は名前と長さだけだが、利用条件の札、絞り込み、モーションの情報は残した。公開できないことが一覧で分かるようにするため。
- **モーションを足す**: 札は「つくる」と「ファイル」の 2 つ。「つくる」は区間を上から並べる 1 つのレシピで、区間の種類は MotionBricks の条件、動画、保管場所のモーション、確認待ちの結果（取り込む前）。開いたときは動画の区間を 1 つ置く。
- **キット**（`docs/edition.md`）: MotionBricks が無いときは MotionBricks の条件の区間も出さず、つなぎの「MotionBricks で作る」を選べなくして理由を出し、つなぎの既定を補間にする。開いたときの区間は動画。
- **区間が 1 つ**: その種類の単体のジョブを積む。動画は「動画から作る」で `video-motion`、MotionBricks の条件は「MotionBricks で作る」で `motion-gen`。どれも結果は確認の欄に出て、見てから取り込む（MotionBricks も確認を通す）。つなぎの作り方は出さない。
- **区間が 2 つ以上**: 「つなぐ」でジョブ `motion-recipe` を積む。使えるのは保管場所のモーション、確認待ちの結果、MotionBricks の条件。動画の区間があると「つなぐ」を押せなくし、先にその区間だけで作って確認待ちの結果を足すよう出す。
- **ファイルの札**: 案は利用条件の 1 欄だが、取り込みに要る権利者、要約、二次配布の 3 つを残した。
- **つなぐ**: 案に無い。「つくる」に区間を 2 つ以上並べたとき。保管場所のモーションか確認待ちの結果（動画の結果、MotionBricks の結果）を選んで「足す」で並べ、区間ごとに開始と終了の秒と速さ（MotionBricks の条件の区間は開始と終了の秒だけ。速さは条件の m/s）、区間の間につなぎの秒（0 でつながない）を書く。条件で作る区間は、種類（「MotionBricks の条件」など）を区間の操作の行に利用条件と並べて出す。並べ替えは ↑ と ↓、外すは「外す」。つなぎの作り方（MotionBricks か補間）は全部のつなぎに共通。「つなぐ」でジョブ `motion-recipe` を積む（`docs/motion-compose.md` の「画面からつなぐ」）。積む前に札の下へ注意を出す: 評価用のみの区間（MotionBricks の条件の区間を含む）が入ると全体が評価用のみになること、個人利用などの区間はその条件が全体に移ること、MotionBricks のつなぎは二次配布 不可になること（見本の動きは使わないので評価用にはならない）、0.53〜1.87 秒の外のつなぎは補間になること、MotionBricks が見つからないこと、確認待ちの結果はつないでも取り込んだことにならず、つなぐジョブが待っているか動いている間は捨てられないこと、並べたあとに取り込んだか捨てた結果があること。
- **つないだ結果の確認**: ほかの確認と同じ右の欄の先頭に出る。区間とつなぎの作り方、「見る」（ビューアで今のキャラに当てて再生する）、継ぎ目の表（コマと秒、速さの最大と関節、1 コマの変化。継ぎ目から離れたコマの 99 パーセンタイルを超えた行は注意の色）、足の滑り、手か肘が胴に入るコマ、部分ごとの値（畳み）、利用条件（札と全文の畳み）、ラベル、モーション ID（既定 `compose-<ジョブ>`）、「取り込む」「捨てる」。
- **確認待ち**: 案に無い欄。確認待ちがあると、右の欄の先頭に比較の動画と「取り込む」「捨てる」の欄が出る。スマホでは足す欄を閉じていても出す。動画から作ったモーションは一覧の 2 行目に対象のキャラ（例「<キャラ> 用（<版>）」）を出し、ほかのキャラに当てているときは注意の色にして、ビューアの見出しにもずれることを出す。
- **速さ**: 刻みは 0.01（標準の 2.3 に合わせられるように）。
- **表情の「古い工程を流す」**: 今ある機能に無いので出さない。工程ごとの「もう一度」で動かす。
- **替える絵**: 自由な場所を指せるよう、選択ではなく候補つきの入力のまま。
- **仕上げ**: 試作の選択は 1 つで、見る撮影、撮る試作、版にする試作を兼ねる。案に無い確かめの種類の切り替え（表情、口の形、視線、表情と視線、角度の表）は、枚数つきの札で残した。表情の撮り比べの差の数字は画面に無いので、撮った枚数だけ出す。元の版の欄は、版に親の記録が無いので出さない。版 ID は `v<版の数 + 1>-<表情づくり>` を入れて畳み、作れないときは畳みを開く。
- **撮る**: 常時出すのはモーションと縦横と「撮る」。写す範囲、画質、長さ、背景、表情、音声、セリフ、セリフを作る、声の種類、長さの要約は「細かい条件」に畳む。タイムラインは案に無いが残した。利用条件の枠は、公開できないときと確かめるときだけ「撮る」の上に出し、それ以外は細かい条件の中に入れる。セリフの再生と消すは、セリフを選んだときだけ出す。
- **作ったもの**: 案の行に、公開の札を足した。行を開くと再生、ダウンロード、削除が出る。
- **書き出す**: 右の欄の下の「ファイルを書き出す」の畳みの中に、VRM と軽量版のリンクだけを置く。入れるモーション、作者、利用条件は機能が無いので出さない。
- **ライブラリの判断待ち**: 案は帯 1 本に数を出すが、キャラをまたぐので 1 件 1 本にした。無いときは出さない。
- **ライブラリのカード**: 進み具合の棒は押すとその工程へ移る（44px）。キャラのメモは出さない。案に無いタグ（`tags`）を、棒の下に小さなチップで出す(スタイルの札のあと)。並べ替えと折りたたみはしない。長いタグは省略し、全文は `title` で出す。
- **表情**: 案に絵は無い。確かめと版にするの 2 行は仕上げへの 1 行にまとめた。「新しい依頼」は開いている工程（3 か 6）に出し、工程の選択をなくした。表情づくりの選択は 2 つ以上あるときだけ出す。
- **つくる**: 案に絵は無い。版の表を先頭にし、このキャラにつながっていないプロジェクトは畳み、説明文を減らした。
- **スマホの表情**: 3D を載せず、依頼の絵を先に見せる。VRM を読むとメモリを使うので、採用と却下に要らないものは載せない。
- **スマホの下のナビ**: ライブラリ、動き、表情、完成モデル、動画(生き物のキャラは ライブラリ、キャラ、動画)。ジョブは上部バーの引き出し。つくると仕上げは案に入口が無いので、キャラの切り替えの欄の「工程」と、ライブラリのカードの棒から入る。
- **ショートの編集画面**: 案の左上は「動画」だが、戻る先はショートの一覧なので「ショート」にした。案に無い保存の状態を題の下に出す(スマホでは保存済みのときは隠す)。スマホの案の「書き出す」は 1 つだが、試しと本番を選べるよう「試し」「本番」の 2 つにした。案の左の列と右の欄に無い今の機能(出演者の編集、型とシリーズ帯、BGM のアップロード、事実の確認、連載、図を作る、書き出した動画の一覧、演出と細かい設定)は畳みと左の列の下に残した。カットの並べ替え、消す、足すはタイムラインの見出しの行に置き、スマホではカットの列の下に出す。「書き出した絵に重ねて見る」は再生の行の右に置いた。案の効果音とテロップの段は決まった位置の見本だったので、書き出しの時間表とカットから作る。出演者の 3 人目の色は案に無いので #F2A0C4 にした。スマホのプレビューの再生ボタンは絵の上に重ねず、絵の下の行に置いた。

## 削除とごみ箱

消す操作はごみ箱へ移すだけで、いつでも戻せる（`docs/characters.md` の「ごみ箱」）。常時目立たせず、控えめに置く。

| 場所 | 操作 |
| --- | --- |
| ライブラリのカード | カードの右下にごみ箱の形のアイコンのボタン（`aria-label` は「<名前> を削除」） |
| つくるの版の表 | 行の末尾の「削除」 |
| 動き | 選んでいるモーションの行の下の「このモーションを削除」 |
| 完成モデルの作ったもの | 撮った動画の行を開いた中の「削除」 |
| 撮るのセリフ | 「このセリフを消す」 |
| ライブラリの下 | 「ごみ箱 N 件、合計 MB」のリンク。`#trash` へ |

- 押すと確認の枠（`confirmDialog`）。影響の箇条書き（`GET .../impact` の `effects`）、「ごみ箱から戻せる。」、「やめる」、「ごみ箱へ移す」。断る理由があるときは、箇条書きの下に理由を出し、「ごみ箱へ移す」を押せなくする。`alert`、`confirm` は使わない。
- 色の強調は確定のボタン（`#FFB454`）だけ。
- `#trash`: 1 行に、種類の札、名前、大きさと移した日、「戻す」、控えめな「完全に消す」。旧形式の項目は「戻す」を押せない。「完全に消す」と「ごみ箱を空にする」は、確認の枠で「戻せないことを確かめた」にチェックを入れるまで確定のボタンを押せない。
- 版を消すと、選んでいた版が無くなった画面は最新の版に戻す（`app.mjs`）。動きの一覧は、合わせたキャラや版を消してあるモーションに「削除済み」と添える。
- ボタンの押せる大きさは 44px 以上（スマホの幅でも）。
