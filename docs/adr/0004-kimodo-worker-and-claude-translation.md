# 0004 文章からのモーションは、常駐の作業プロセスの Kimodo と、claude -p での英語への変換で作る

日付: 2026-10-31

## 決めたこと

- 文章からのモーションは Kimodo-SOMA-RP-v1.2 で作る。Kimodo は自分の `.venv`（Python 3.10。置き場は `config.json` の `kimodoDir`）で、きゃらすたの `tools/kimodo_worker.py` を動かす。Kimodo のリポジトリは変えない。
- `tools/kimodo_worker.py` は常駐する作業プロセスで、標準入出力の 1 行 JSON で話す。モデルの読み込み（約 10 分）を 1 回で済ませ、最後の使用から 15 分で終了する。PID は保管場所の `jobs/kimodo-worker.json` に記録し、サーバーの終了時にその PID の木だけを止める。
- 文章の埋め込みは文章ごとにキャッシュする。
- 日本語の文章は、`claude -p` を別プロセスで呼んで英語の説明文（10 秒以内の区間の並び）にしてから Kimodo に渡す。文章は外部へ送られるので、ボタンを押したときだけ行う。文章は引数の配列と標準入力で渡し、shell には渡さない。
- 候補は seed を変えて複数作り、動画のかわりにビューアで再生して、1 本だけ取り込む（確認待ち。動画からのモーションと同じ形）。
- 見本の動き（MotionBricks の BVH）は使わないので、`evaluationOnly` は付けない。ライセンスの記録は条件の事実（NVIDIA Open Model License、LLM2Vec は MIT、Llama 3 は Community License と Acceptable Use Policy の案内）だけを書き、商用で使えるかの判断は書かない。`redistribution` は判断をしていない既定の false。

## 理由

- 読み込みが 541〜635 秒かかり（D: が HDD で RAM が足りない）、生成は 4〜7 秒、1 文のエンコードは 3〜8 秒。ジョブのたびに読み込むと使えないので、読み込んだまま待つプロセスが要る。常駐の時間は、続けて何本も作る使い方に合わせた 15 分。
- Kimodo の環境（Python 3.10、torch、peft）をきゃらすたの環境と混ぜない。きゃらすたは依存パッケージなしの Node のサーバーなので、別プロセスに分ける。
- 日本語のままだと意味が崩れた（実験）。「A person …」で始め、動作の順番を明示した英語にすると良かった。1 区間は 10 秒まで（15 秒の単発は hips が 3.9 m まで上がって壊れた）なので、変換の段で区間にも分ける。
- `claude -p` にツール・MCP・スキル・設定を読ませないと、1 回約 5 秒、約 0.005 USD。読ませると約 13 秒、約 0.5 USD（入力が 128k トークンになる）。
- 作業プロセスは標準入力が閉じたら、今の処理が終わってから終了する（処理の途中でサーバーが強制終了されたときは、その処理の間は残る）。前のサーバーの PID の記録は、持ち主を確かめられないので止めず、知らせるだけにした。
- Llama 3 の利用は Acceptable Use Policy に従う条件があるので、記録に案内を残す。

## 考えた別の案

- ジョブのたびに Kimodo を起動する。読み込みで 1〜2 分（HDD では 10 分）かかるので採らない。
- 日本語のまま Kimodo に渡す。意味が崩れるので採らない。英語への変換をきゃらすたの中の辞書で行う案も、自由な文章を扱えないので採らない。
- Kimodo のモデルをきゃらすたのサーバーのプロセスに読み込む。Node から Python のモデルは読めない。
- 文章を送るかをジョブごとに確かめず、設定で常にオンにする。文章が外部へ送られるので、ボタンを押したときだけにする。
