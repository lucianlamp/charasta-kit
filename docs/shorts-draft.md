# ショートの下書き

テーマからカット表の下書きを作る（`short-draft` ジョブ）。作り手は Claude（`claude -p`）か Gemini（依頼文を Gemini に貼り、答えを取り込む）。人が読んで直してから、`short` ジョブで書き出す（`docs/shorts.md`）。用語は `CONTEXT.md` の「下書き」から「次の話」まで。

## 画面

- 作り手: 「テーマから作る」と「次の話を作る」で Gemini か Claude を選ぶ。既定は Gemini。Gemini では「依頼文をコピー」で依頼文を作り、Gemini の答えを欄に貼って「取り込む」を押す。答えに問題があれば理由の一覧と「直しの依頼文をコピー」を出す。スマホの http でクリップボードが使えないときは欄の文を選ぶ。一覧と編集画面に下書きの作り手を出す。
- テーマから作る: 一覧のボタンで欄を開く。テーマ、型、長さ、出演者（名前、キャラ、声）、補足を入れて「下書きを作る」を押す。ドラマは 2 人から始まり、3 人まで足せる。ジョブは `short-draft`（下の「short-draft ジョブ」）。一覧に進み具合が出て、できると編集画面が開く。下書きは必ず新しいショートになり、既存のショートは変えない。
- 図の提案: 下書きのカットに図の説明（`figureNote`）があり、図がまだ無いときは「演出と細かい設定」と、タイムラインの図の段(点線)に出る。説明は同じ畳みで直せる。
- 下書きの注意: 直させても基準から外れたままの所（字数、長さ）を左の列に出す。
- 事実の確認: 雑学など語りの型の下書きに出る欄。主張ごとに確かさ、確認に使う語、出典のリンク、「この主張を消す」を出す。Gemini の答えの主張は `claude -p` が別に確かめた結果を出す。出典の無い主張には「要確認」の札と「人が確認した」のボタンを出す。確かめたあとにセリフかテロップを直すと全部が要確認に戻り、「直した文を確認した」を押すまで本番を止める。要確認が 1 件でもあると欄が開き、「本番を書き出す」を押せず、理由を 1 行出す。サーバーも断る（409）ので、カードの「本番で書き出す」からも通らない。試しは書き出せる。
- 連載: ドラマの編集画面の左の列に出る欄。連載の名前、登場人物（1 行に 名前: 設定）、あらすじ、未回収の伏線（1 行に 1 つ）、次の話の方向を直せる。古いドラマは空の欄で出る。「次の話を作る」は編集を保存してからジョブを積み、できると新しいショートの編集画面が開く。第 2 話以降は「前の話を開く」のリンクが出る。

## short-draft ジョブ

テーマからカット表の下書きを作る。コードは `lib/short-draft.mjs`。動画は作らない。人が読んで直してから `short` ジョブで書き出す。

入力: `theme`、`style`、`seconds`（10〜60、既定は雑学 20、ドラマ 25）、`cast`、`note`。前の話の出演者、版、BGM が消えているときと話数が上限のときは積む時点で断る。次の話は `fromShortId` と任意の `theme`、`note` で、型はドラマ、出演者、声、シーン、BGM（音声ファイルと既定の BGM）、環境音を前の話から取る。入力の `cast` は使わない。連載の無い古いドラマは、カットだけを渡して第 2 話として作る。

1. **一覧を作る**: シーンは `stages/catalog.json`、動きは ID が `talk-` か `act-` のモーションをその場で読み、VRMA から姿勢を測る（`motionPose`）。顔の下向きの中央値が 20 度以下、顔の左右の幅が 15 度以下、hips の移動が 0.3 m 以下の動きと `talk-` と手紙を持つ動きだけを「話すカットの動き」にし、残りは「聞く人だけの動き」として分けて渡す。話す人とセリフの無いカットの撮られる人が聞く人だけの動きなら errors にする（`act-lean` は顔が 30 度下を向き、最後のカットで顔が見えなかった）。表情、カメラ、音、演じ方、転換、効果、テロップの型と一緒に標準入力の文へ入れる。次の話のシーンは前の話のものに絞る。
2. **claude -p を呼ぶ**: 呼び方は `motion-text` と同じ。モデルは `CHARASTA_CLAUDE_MODEL`（既定 sonnet）。テーマ、補足、一覧は標準入力で渡し、引数の system prompt には型ごとの基準だけを入れる。ドラマはツールなし。雑学、派手、ニュースは `--tools WebSearch,WebFetch` と `--allowedTools` で 2 つだけ許す。ファイルとシェルのツールは許さない。上限は Web あり 10 分、なし 4 分。
3. **確かめる**（`checkDraft`）: 長さの上限（`LIMITS`。プロンプトにも書く）、一覧に無いもの、話す人の間違い、手紙の無い手紙のカメラ、主張の空、連載の空は errors。1 区切り 10 字を超えるセリフ、長さの目安の 20% を超える差、ドラマの 1 カットが 3〜7 秒の外、定型の呼びかけ、全身が映るカメラが続く雑学、強調の印や図の提案が無い雑学は warnings。最後に `shortBody` を通す。
4. **直させる**: errors か warnings があれば、前回の答えと直す所を渡して 1 回だけ直させる。検索はさせず、`claims` に無い事実を足させない。1 回目と文が同じ主張だけが 1 回目の出典を持ち、足した主張は要確認になる。直しの claude が失敗するか答えが使えず、1 回目が保存できるなら、理由をログに残して 1 回目を使う。それでも errors が残れば失敗にする。warnings は `short.json` の `draft.warnings` に残して画面に出す。
5. **保存する**: ID は `s` + ジョブ ID の続き。既存のショートは書き換えない。`draft` にテーマ、補足、ジョブ、モデル、直させたかを残す。作業フォルダに `prompt.txt`、`reply-*.txt`、`stream-*.jsonl` を残す。

カットの欄 `figureNote` は図の説明で、下書きでは絵を作らない。図は `short-figures` ジョブが作る。語りの型の `seconds` は 0 にして声で長さを決める。`tone` は話す人が ElevenLabs のカットにだけ残す。演じ方は `whispers`、`sad`、`angry`、`excited`、`nervous` に絞る。`sighs`、`crying` は息や泣き声が文に入り、`trembling`、`terrified` は声を揺らすので、日本語の読みが崩れやすいと見て外した。聞き比べはしていない。手動で選ぶ欄はこれまで通り全部出る。`act-offer` の出演者には相手の方へ 30 度足し、姿勢を保つ（見本と同じ）。

ドラマの基準には、絵で確かめて足した決まりがある。手紙の絵に描いてある文を渡し、セリフをそれに合わせる（渡す前は、画面の「ひよりは、全部知っている」とセリフの「私の名前がある」が食い違った）。話す人に体の向きが変わる動きを使わない（歩み寄る動きで話す人が背中を向けた）。`face_who` と `close_who` の人に動く動きを使わない（顔が画面から外れた）。第 2 話からは最初のカットのテロップを消す（上の帯と重なった）。`over_shoulder` と `face_who` のカットは小道具を外す（手紙が手前に白くぼけて顔にかかった）。雑学の基準には、1 つの尺度で掘り下げる、驚きにならない説明のカットを書かない、記録の数字は新しい値を確かめる、がある。

長さの目安: VOICEVOX は速さ 1.25 で 1 字 0.12 秒、カットごとに 0.22 秒足される。ElevenLabs は 1 字 0.21 秒。`cutEstimate` と `memberSpeed` はこの値に合わせた。

Gemini の流れ（`source: 'gemini'`）: 本文は作らず、貼られた答えを確かめて取り込む。

- `POST /api/short-draft/prompt`: 本文は `theme`、`style`、`seconds`、`cast`、`note` か、次の話の `fromShortId`、`note`。答えは `{prompt}`。claude と同じ基準と今のライブラリの一覧で作り、調べ方だけ Google 検索の文に替える（`draftRequest`）。
- `POST /api/short-draft/import`: 同じ本文に `answer`（60000 字まで）を足す。積めれば 201 でジョブを返す。問題があれば 422 で `{error, errors, warnings, fixPrompt}` を返し、ジョブもショートも作らない。`fixPrompt` は Gemini の同じチャットへ貼る直しの依頼文。
- 答えは外部の入力として扱う。括弧の対応が取れた JSON の塊のうち読める一番長いものを使うので、前後の説明文とコードの囲みは付いたままでよい（`parseDraft`）。使う欄は `draftBody` が選んだものだけで、`confirmed`、`cast`、`draftBy` などの答えの値は使わない。HTML のタグは errors にする。基準から外れる warnings は止めずに `draft.warnings` へ残す。ただし見積もりの長さが目安の 1.3 倍を超える答えは 422 にして、`fixPrompt` で削る字数を指示する。
- 語りの型は、取り込みのあとで `claude -p` が台本から主張を抜き出し直して確かめる（WebSearch と WebFetch だけ。`FACT_SYSTEM`）。台本と Gemini の主張はデータとして渡す。主張に番号を付けて全部の結果を返させ、結果の無い番号は出典なし、確かさ low で残す。足された主張は後ろへ付ける。`supported` が真で、検索の結果に出たか開けた URL だけを出典に残す。Gemini が付けた URL も同じ扱いで、書いた本人の確認は出典にしない。この claude が失敗したとき、結果が空のとき、合計が 20 個を超えるときは、取り込みは止めず、主張を全部確かさ low の要確認にして `checkedBy` を空にする。ドラマは claude を呼ばない。
- `short.json` の `draftBy` は下書きの作り手（`claude`、`gemini`）。`draft.checkedBy` は主張を確かめたモデル。スキルは `gemini-short-script`。

語りの型の話すカットの動きは `talk-` だけ。ドラマは測りを通った `act-` の動きも使う。最初のカットのテロップがセリフと語の並びの 6 割以上重なるときは消す。字数を合わせるための読点の疑い（「直接嫌がらせを、していない」）と、図の説明があるのに `[語]` の無いカットは warnings にする。図は `[語]` が無ければカットの頭から 0.2 秒で出る。出るときの pop はセリフと重なるので、ほかの pop の 2 倍の強さで鳴らす。

カット全体の表情に `happy` と `relaxed` を使わない。どちらも目を閉じるので、長く続くと目の見えないキャラになる。答えにあれば `neutral` に直す。笑顔は `[語|happy]` の短い区間だけで、問いのカットでは外す。

事実の確認: `claims` は `{text, confidence, query, sources: [{url, title}], confirmed}`。claude の出力を `stream-json` で読み、WebSearch の結果に出た URL と、失敗しなかった WebFetch の URL だけを出典に残す（`readDraftStream`、`vetClaims`）。答えに書かれただけの URL は落とす。`sources` が空で `confirmed` が偽の主張は要確認で（`pendingClaims`）、`shortJobInput` が `final` を 409 で断る。ジョブは保存時に全カットの文とテロップのキー `scriptKey` を残す。今の台本とキーが違えば主張を全部要確認にして、同じく 409 で断る。強調の印の直しではキーは変わらない。人が「直した文を確認した」を押すとキーを今の台本に更新する。

連載: `serial` は `{name, episode, previousId, characters: [{name, note}], synopsis, threads, next}`。ドラマの下書きで作り、次の話は前の話の `serial` とカットのセリフを渡す。前の話は変えない。題は `<連載> 第N話 <題>`、シリーズ帯は `<連載> 第N話`（20 字まで）にする。

`CHARASTA_FAKE_DRAFT=1` で claude を呼ばず、決まった答えを返す。Gemini の答えの確かめは `https://example.org/seen` だけを検索で見た URL として扱い、`check-fail` は確かめの claude の失敗。`bad-json` は最初の答えが JSON でなく、直すと通る。`bad` は直しても JSON でない。`warn` は字数の warnings が残る。`claude-fail` は claude の失敗。テストはこの経路だけを使う。
